下表的机体系速度与被动 yaw 描述适用于原四个任务；`walk` / `spin` 使用水平轮轴速度，`spin` 启用世界 yaw PD。

## 已整理到独立工程

- 单层 DirectRLEnv 入口、独立配置/PPO，不再经过 V13/V14/25_v3。
- 站立、站高、速度、原地跳跃，以及新增的行走和云台定向小陀螺配置工厂。

- 沿用原命令采样与跳跃阶段调度；弹簧控制、质量/惯量随机化、世界系外力/力矩脉冲仍由原组件处理。
- 真正离地和稳定落地判据、分阶段奖励、按真实回合时长记录奖励。

## 有意重新定义的部分

这次是新实现，不是将旧行为原样折叠到一个文件。

| 项目 | 新实现 |
| --- | --- |
| 复位 | 完整标定静息姿态 + 根 yaw 随机化；没有旧版差分 IK 随机腿长 |
| 电机 PD | 组件在物理子步算力矩；Isaac 执行器零 PD、接收力矩前馈 |
| 速度 | 直接机体系 vx/wz；不再使用旧版 pitch 投影修正 |
| 奖励 | 独立精简奖励表，数值在 settings.py；不等价于旧总奖励 |
| 观测 | Actor 35 / Critic 60，显式动作顺序；旧 Critic 为 78 |
| 随机化 | 质量/外力默认关闭，需明确打开；没有隐式继承旧 EventCfg |
| 弹簧 | 单一控制器，当前名义线性曲线与总阻尼集中配置，无隐藏力叠加 |
| 云台 | yaw 为被动阻尼，pitch 使用独立零位 PD 保持；均不占用六维策略动作 |
| 跳跃 | 独立数据组件；不调用旧 jump_takeoff.py，也没有辅助抬升 |
| 日志 | 用实际回合时长归一化，不能直接与旧 reward 数值横向比较 |

## v2_0 机器人映射

默认配置已切换到 `assets/v2_0.json`。原来四个腿部策略关节映射如下；动作槽位顺序保持旧策略的前腿/后腿排列，并在 `directions` 中处理左右关节坐标符号。

| 旧策略关节 | v2_0 关节 | 策略方向 |
| --- | --- | ---: |
| `left_front1_joint` | `left_leg_1_joint` | +1 |
| `left_rear1_joint` | `left_thigh_joint` | +1 |
| `right_front1_joint` | `right_leg_1_joint` | -1 |
| `right_rear1_joint` | `right_thigh_joint` | -1 |
| `left_wheel_joint` | `left_wheel_joint` | +1 |
| `right_wheel_joint` | `right_wheel_joint` | -1 |

v2 的弹簧自由度是 `left_spring_2_joint` / `right_spring_2_joint` 两个移动关节；云台 yaw 为辅助阻尼，pitch 为辅助位置保持。其余 20 个可动连杆关节归入被动组。6 个闭链约束不计入 articulation 的 30 个策略/辅助自由度，模型转换时保留为 PhysX 闭链约束。零位姿基于 CAD 中各连接锚点一致的姿态，机器人根改为 `base_link`，地面轮底高度对应 `rest_height=0.372790959 m`。

`CommandSampler` 的速度/转向命令混合采样和 `JumpController` 的自动触发、起跳、落地阶段调度沿用原实现，没有因关节重命名而改变。v2 的关节动作方向加入观测和 checkpoint 契约，因此 v1 checkpoint 不可直接加载。

### 坐标、驱动和弹簧

已对比两版 USD 的实际关节轴：旧版右侧轴为 -Y，新版左右轴均为 +Y。因此控制输出、关节位置偏差、
速度观测和 Critic 力矩都使用上述方向映射；动作历史和动作变化奖励保持策略坐标。
新零位通过每个关节的两端锚点及转动坐标核对，不能套用 v1 的折腿静息角。

原 `base_link` 相对资产根的位置是 `(0.17020701599, -0.005903785705, -0.0695)` m。
转换整体平移所有刚体，使 base 坐标与生成根坐标重合，并把 ArticulationRootAPI 放在 base 上。
局部网格、质量、惯量、关节局部坐标、限位、碰撞体和闭链连接保持不变。
原 CAD 伺服全部移除，包括右侧 `connect_05` 的额外驱动；运行时统一由代码执行器控制。
终止接触体新增 `gimbal_pitch_link`；轮子刚体索引和传感器索引独立解析。

站立高度取模型的 `rest_height`；height、velocity、jump 的命令范围和时序沿用，其实际可达性待仿真检查。
弹簧 `offset=None` 时压缩参考取各自的模型复位位置：v2 为 0，v1 为 -0.0482 m。
原预载 400 N、刚度约 2857.14 N/m、阻尼 50 保留，可显式设置 offset 覆盖。
初次迁移的云台 pitch 为被动阻尼；站姿诊断后按用户要求改为独立位置保持，不占用动作维度。

观测契约升级为 `wheel-legged-composition-v2`，额外记录方向、站高、轮半径及弹簧配置。
没有转换旧神经网络权重；相同输入输出维度不能证明权重可复用。
`components/commands.py`、`components/jump.py` 和 `ppo.py` 的内容及哈希保持不变；
环境生命周期的调度顺序、控制步 0.02 s、物理步 0.005 s 也保持原样。
`components/rewards.py` 已按后续授权加入姿态项及指标，初始版本哈希保存在 `MODEL_MIGRATION.json` 的 `posture_update` 中。

### 重建

在工程根目录用现有 Python 执行 `scripts/migrate_v2_model.py`，可由 `model/v2_0.usdz` 重新生成
v2 USD、JSON 和 `MODEL_MIGRATION.json`。原 USDZ 不会被修改；重建会覆盖生成配置，手工调整过时需先保留修改。
脚本只加载独立 USD 库，不启动 Kit，也不安装依赖。重建后执行 README 中的三条验证命令。
已通过 USD 离线检查和 11 项 CPU 测试，并完成短时回放；后续姿态修改见 [POSTURE_CONTROL.md](POSTURE_CONTROL.md)。

## 此版未迁移

粗糙地形、台阶/坡道状态机、小陀螺世界系平移、旧版 HIM/DreamWaQ、观测历史堆叠、
旧 CSV 电机曲线加载、旧键盘图形面板和 USD 模型本身的几何改造。
它们需要在新的组件接口上逐项补充，不能通过重新引入旧环境祖先类实现。
原 `velocity` 转弯/原地旋转是 vx/wz 命令；新增 `spin` 实现原地旋转与云台世界 yaw 保持，尚不支持世界系平移。

## 完整体接入前的物理事项

闭环连杆在 PhysX 中的运行行为、弹簧曲线、输出轴力矩/速度和正负方向，需要等可行性测试时确认。模型转换脚本检查了 USD 连接锚点、轮半径和轮底高度，但没有通过仿真证明动力学假设。

## 旧训练隔离

没有修改旧任务注册、训练脚本、日志或 checkpoint，也没有停止、重启或轮询训练进程。
依赖使用原 Python 环境；没有安装、卸载或升级包。
等用户确认之前的训练结束后，再开始新工程运行测试。
